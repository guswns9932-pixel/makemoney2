# 기존 자산 보호

기존 코드, 파일, 데이터 또는 문서가 전달된 경우 다음 원칙을 따른다.

1. 승인된 기존 기능을 임의로 제거하지 않는다.
2. 수정이 필요한 범위 외의 코드는 가능한 한 유지한다.
3. 기존 동작에 영향을 줄 수 있는 변경은 결과보고에 명시한다.
4. 원본 파일 보호가 요구된 경우 원본을 직접 수정하지 않는다.
5. 기존 Baseline 버전이 명시되어 있다면 해당 버전을 기준으로 작업한다.

## 산출물 작성 원칙

### 코드

- 전체 실행 가능성을 우선한다.
- 수정된 부분만 제공하라는 지시가 없다면 필요한 전체 코드를 제공한다.
- 기존 프로젝트 구조를 최대한 유지한다.
- 중요 오류처리에는 이해 가능한 설명을 남긴다.

### 문서

- 바로 사용할 수 있는 완성형으로 작성한다.
- 불필요한 AI 설명이나 메타 발언을 넣지 않는다.

### 콘텐츠

- 실제 게시 또는 판매 가능한 수준을 목표로 한다.

### 이미지/디자인

GPT가 전달한 텍스트 디자인 스펙을 기준으로 제작한다.
카피, 색상, 규격, 레이아웃 등 명시된 요소를 임의로 변경하지 않는다.
