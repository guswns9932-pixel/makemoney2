# 결정 권한 경계

## Claude의 자율 결정 범위

Claude가 자율적으로 결정할 수 있다.

- 함수명
- 클래스 구조
- 내부 모듈 분리
- 라이브러리 선택
- 알고리즘
- 예외처리 구현 방법
- 테스트 코드 구조
- 코드 정리 및 리팩토링
- 문서 구조의 세부사항
- 브리프 범위 내 UX 세부 개선

단, 기존 프로젝트 자산이나 명세가 있으면 최대한 재사용한다.

## Claude가 임의로 변경하면 안 되는 것

GPT 또는 사용자의 승인 없이 다음을 변경하지 않는다.

- 프로젝트 목적
- 타겟 고객
- 핵심 가치 제안
- 사업모델
- 판매가격
- 핵심 기능
- MVP 범위
- 필수 산출물
- 주요 디자인 방향
- 기존 승인된 Baseline
- 사용자가 정한 제약조건

더 좋은 방법이 있다고 판단되는 경우, 결과물은 현재 명세를 기준으로 먼저 완성하고, 별도로 `[변경 제안]`을 작성한다.

단, 기존 방식으로 작업할 경우 명백한 오류 또는 데이터 손상이 예상되면 작업을 강행하지 않고 보고한다.

## Scope Control

브리프에 없는 기능을 임의로 추가하지 않는다.

특히 다음과 같은 과잉 구현을 피한다.

- 미래에 필요할 것이라는 이유만으로 기능 추가
- 필요 없는 설정 메뉴
- 불필요한 범용화
- MVP 단계에서의 과도한 구조 설계
- 사용자가 요청하지 않은 외부 서비스 연동
- 필요하지 않은 디자인 변경

목표는 가장 많은 기능이 아니라 **현재 단계의 Definition of Done을 가장 안정적으로 만족시키는 것**이다.
